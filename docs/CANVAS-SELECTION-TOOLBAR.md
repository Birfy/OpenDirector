# 节点选择、上下操作栏与生成结果

2026-10-27。本轮把单选节点的媒体操作与下方生成参数分开。主画布负责根据选中节点与可用区域定位；`NodeSelectionToolbar` 本身不参与画布缩放。

## 原站依据与本地映射

本轮原站交互观察：空视频节点没有顶部操作条；已上传图片显示顶部条；已有生成结果的视频可同时显示顶部操作与下方生成参数。媒体操作条按单选节点的类型与内容呈现，不应因只创建一个空媒体节点就出现完整后期处理按钮。

以下发布包为静态证据，证明入口、调用路径和条件，不单独证明当前账户可调用全部服务：

- `research/canvas/readable/js/545ec3537fff-main.303f6eac20.js:16051`：图片 `outpaint`、`image-hd`、`cutout` 和视频超清。
- 同文件 `:16426`：`smart-edit`；`:16450`：`video-edit`；`:16473`：`video-extend`。
- 同文件 `:16509`：视频首帧、尾帧、自选截帧子菜单；`:16558`：深度动作捕捉；`:16582`：视频时长裁剪。
- 同文件 `:16617`：声音分离子菜单区分提取音轨与独立的音源分离能力，且各自受能力开关约束。
- 同文件 `:16792`：视频工具；`:16870`：多角度；`:16878`：打光；`:17224` 附近：图片构图、网格切分与标注工具。
- 同文件 `:17294`：AI 助手；`:17348`：图片预览；`:17383`：视频预览；`:17408`：下载；`:17512`：局部重拍。

## 交互约束

- 操作条位于画布缩放容器之外，按钮保持屏幕像素尺寸；父级通过 `style` 或外层容器控制位置及实际最大宽度。
- 窄窗口可横向滚动；按钮支持左右方向键、Home/End，移动焦点时滚动到当前按钮。
- 每个按钮复用已有 `TooltipButton`，支持鼠标悬停与键盘焦点；提示通过 portal 显示，不被横向滚动容器裁掉。
- 指针与键盘事件不交给下方画布拖动/删除快捷键；双击按钮不会同时打开节点编辑器。

已通过 React 服务端实际渲染断言：空/缺失媒体无条，图像与视频动作按类型分开，时间线无无效下载入口，锁定时编辑禁用但保留下载。此检查不覆盖点击、悬停或位置，集成后的实际浏览器验收另行记录。新增入口不等于所有原站后端、参数子菜单及视觉细节已达到完全一致。

## 选中布局与生成结果修复

本轮在已登录的 Brave 实际观察原站：选择已有生成视频后，顶部工具栏与底部生成栏一起出现，视口向上平移为下栏留出空间；原站创建空视频节点没有弹出编辑模态框，只有下方生成栏。测试创建已撤销，原站恢复为 2 节点、1 连线，没有调用模型或消费积分。

原站发布包 `research/canvas/readable/js/e02221c0211e-canvas-core.04e59616e1.js:62340` 附近的 `resolvePresentationValue` 同时处理节点主区域、屏幕尺寸装饰、安全区域与起始视口。静态代码支持这种布局结构，不代表本地参数与原站逐像素相同。

- `useSelectionPresentation` 统一拥有选中节点、上栏和下栏的屏幕几何；测量包含实际栏高、换行和左右侧面板。自动调整仅平移/缩放视口，不修改节点的尺寸与世界坐标。手动拖动、缩放会取消本层拥有的定位动画；拖动结束只跟随，不把节点拉回。
- 测量绑定节点和控件归属，避免新图片继承上一视频的生成栏高度。同一次选择以同一个起始视口计算多帧测量，避免连续缩小；若新目标等于当前位置，仍取消排队的旧动画。
- 正常生成通过 `applyGenerationResults` 原位写入第一个结果，保留节点 ID、标题、尺寸、位置和引用。批量额外结果独立排布，不新增虚假的输入边。截帧、裁剪等显式派生操作仍创建结果节点及来源边。
- 任务历史保存冻结的结果归属，刷新后的结果同步使用同一路径；实时与恢复路径避免重复接收。节点已删除、锁定、换素材或切换项目时，结果保留在任务历史/原项目中，不覆盖不再匹配的来源。
- 新上传/素材库导入及本地派生素材标记为 `mediaRole: asset`，选择时只显示编辑工具栏。生成节点/生成结果为 `generation`。旧文档没有来源标记时保留原生成栏行为，不猜测其历史来源；存储校验、复制与撤销比较保留此字段。
- 视频/音频本体首次点击可选中节点；原生播放控制保留。生成参数、相机、配色、风格等弹层在视口内定位并可滚动，Esc 只关闭当前弹层；插入引用保留提示词光标位置。

## 实际浏览器验收

独立 `localhost` 测试文档使用本机合成的 2 秒 MP4；不是模型输出，也未调用付费 API。

| 场景                                 | 实测结果                                                                               |
| ------------------------------------ | -------------------------------------------------------------------------------------- |
| 空视频节点 → 整理请求 → 导入视频结果 | 1 节点、0 连线保持不变，原节点得到可播放视频；另一个既有测试文档也保持 10 节点、2 连线 |
| 点击已有视频 / 空视频 / 上传图片     | 已有生成视频显示上下栏；空视频只有下栏；新上传图片只有上栏，刷新后仍然如此             |
| 拖动视频标题                         | 节点与两栏移动 150×34 px，视口 transform 不变，编辑弹窗数量为 0                        |
| 显式“截取帧”                         | 打开本地取帧器，确认后新增图片与来源边，保留原视频                                     |
| 1280×720，适应选中视频               | 上栏 y=72..118，节点 y≈158..328，下栏 y=344..642，无重叠                               |

| 780×620 窄屏及右侧 AI 面板           | 上下栏限制在可用宽度；开启侧栏后操作栏与侧栏留 16 px 间隔                              |
| 生成参数弹层与 Esc                   | 弹层未超出窗口，可滚动；Esc 后节点与生成栏仍保留                                       |

`npm test` 180 项通过；`npm run build` 通过。构建仍有画布/导演台超过 500 kB 的既有块大小提示。测试覆盖原位结果、批量乱序、历史恢复与冲突、几何和边界；浏览器覆盖真实文件选择与播放、选择、拖动、弹层和布局。本轮没有真实模型 API 端到端复测，也没有把全部工具子菜单宣称为完全对齐。

干净浏览器会话完成选择/搜索后的 error/warn 为 0；开发标签页包含修改 Hook 结构时产生的旧热更新错误，已刷新确认恢复。用户原「光与山之间 · 镜头研究」刷新后仍为 17 节点、15 连线，未改动素材和节点结构。[最终操作栏截图](canvas-selection-layout.png)。
