### 真实浏览器点验

以下操作在本地应用中完成，媒体文件未上传至第三方。

- 图层板在 1200×1000 图片上新增文字，设置 Y=90、旋转 −5°并锁定；锁定后变换与排序禁用。底图擦除一笔，撤销/重做，再合成实际 PNG。刷新及 JSON 导入后重新打开，文字、锁定和一笔蒙版仍可编辑。
- 时间线导入 3 秒 MP4 与 3 秒 WAV，视频设为 2×；两张各 3 秒图片加视频，视觉轨总时长为 7.5 秒。播放时实际 HTMLVideoElement 的 `playbackRate=2` 且时间推进。分割与撤销、JSON 导出、音轨保存经过点验。
- 主体保存描述、原图、1 张辅助图与 3 秒声音。刷新后界面和导出数据保留这些内容。
- 导演台实际 WebGL 渲染人物和方块，修改物体与镜头位置，在 0/6 秒记录关键帧并播放。应用后保存场景与截图，重新打开仍有两个关键帧；按需加载正常。
- 视频取帧输出原尺寸 640×360 PNG。将 3 秒素材的 0.5–2 秒范围重编码，结果为可再次打开编辑的 640×360 WebM，浏览器读得约 1.566 秒（重编码精度受帧调度影响）。实际下载文件经 ffprobe 确认为 VP9 + Opus。
- 同一范围提取的 WAV 实际时长为 1.500 秒、48 kHz、单声道 PCM16；实际下载成功。单元测试另核对 RIFF 字节、交错采样、边界和饱和处理。
- 修复录制 Blob 的 MIME 参数含逗号导致 data URL 无法播放的问题，修复内嵌媒体下载，并监听后续时长更新。修复重复操作的结果节点重叠；浏览器导出的四个新节点通过几何检查，未与现有节点重叠。
- 生成任务 A 取消，任务 B 导入原站实测 T01 的 2048×2048 PNG；历史中 A 仍为本地草稿，只有 B 标为已导入结果。没有调用计时器伪造 AI 完成。
- 从真实导出文件制作两节点验收副本并通过文件选择器导入，新建独立项目 ID。⌘A 全选后创建堆叠、切换当前素材、调整顺序并保存；导出数据中的成员和顺序正确。
- 1200×1000 图片按 2×2 拆分，得到四张 600×500 PNG 与来源连线；一次撤销移除整批，重做恢复。
- 主画布导出包含 12 节点、11 连线；生产 `parseDocument` 校验成功，保留图层、时间线、主体、导演台和媒体数据。IndexedDB 刷新恢复经过点验。
- 桌面 1440×900 与窄屏 390×844 点验；窄屏时间线对话框宽 370，页面滚动宽度等于 390。窄屏隐藏顶栏导出按钮时，“更多操作”仍提供 JSON 导出。测试后恢复正常视口。

## 恢复代码

恢复校验与运行应用的构建是独立的。`npm run recovery:check` 会校验保存的原文件、AST 提取区间、派生文件、source map 和静态依赖清单，并报告工具错误、语法错误和未知依赖。

最终实际运行结果：所有原文件/派生文件摘要、提取区间、source map 目标及保存清单核验一致；发现 104 条工具警告，其中 1 条 error-class，独立解析也发现同一处语法错误（`module-fg_2.js` 重复声明）。因此严格检查按设计返回 **exit 1**，不能列为全通过。

精确统计、未解析依赖和故障路径见 [恢复报告](../recovered/README.md) 与 [机器清单](../recovered/inventory.json)。这不是完整原站应用通过构建的证明，也没有通过删除诊断来改变结论。
