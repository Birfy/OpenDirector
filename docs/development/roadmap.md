# 发展路线与交付门槛

本路线按能力依赖组织，不是完成进度表。原则见 [开发指导](../../AGENTS.md)，对象及执行语义见 [统一项目架构](../architecture/unified-project.md)。具体任务、缺陷和执行结果记录在 Issue、PR 及提交说明中。

## 推进方式

优先形成可独立完成创作的画布，同时建设背后的业务服务，再通过工具开放给 Agent。按能力逐项推进，接口与持久化不能等到 UI 全部完成后才设计；也不必等所有功能齐备才验证 Agent 接入。

同一能力沿“手动操作 → 正式业务提交 → 重开恢复 → 工具调用 → 交错编辑”的路径验收。需要重构时保留可验证的用户能力，不以切换架构为由丢弃高级编辑、时间线或模型支持。

## 工作包与依赖

| 工作包 | 交付范围 | 关键依赖 | 验收门槛 |
| --- | --- | --- | --- |
| 工程与素材基础 | 稳定身份、文件登记、提交恢复、回执、对象版本 | 明确对象契约 | 重启后事实一致，响应丢失重放不重复写入 |
| 画布创作闭环 | 创建、引用、生成、候选采用、隐藏和历史 | 工程与素材基础 | UI 可完成操作，参考、执行来源和采用相互独立 |
| 编辑与视频编排 | 主体、图层、媒体编辑、时间线和真实导出 | 稳定素材与编辑文档 | 重开可继续编辑，输出可播放且来源可追溯 |
| 公共能力与同步 | 类型化命令、查询、能力说明、依赖保护和变更通道 | 对应业务能力 | 绕过 UI 调用仍遵守相同规则，断线后状态可恢复 |
| Agent 协作 | 工具适配、会话草稿、消息快照、执行关联 | 公共能力与同步 | Agent 和用户能相互继续编辑，交错操作不丢失内容 |
| 自主编排 | 目标拆解、依赖安排、结果观察、恢复与后续决策 | 可查询和可恢复的基础操作 | 在授权范围内连续推进，未知状态不盲目重发 |
| 默认入口收敛 | 完整业务接入、过渡路径退出、使用说明 | 所需创作与协作能力完成验收 | 只有一份权威工程，缓存可重建，关键体验不退化 |

这些是工作范围，不代表要新增同名系统、数据库或单独服务。工具任务可保留自己的类型，但需要统一来源、依赖检查和事件；渲染位置按实际需求确定。

## 一项能力的完成标准

1. 对象归属、调用参数、允许状态和失败语义明确。
2. UI 与工具调用进入相同应用服务，遵守类型、版本、锁定和模型限制。
3. 保存的不只是展示效果，还包括所需文件、结构、来源和执行依据。
4. 取消、失败、重试、项目切换和重新打开不会错误覆盖或重复执行。
5. 正式变更可被另一入口查询，并在界面中正确显示。
6. 有与风险相称的验证；未覆盖的真实服务、媒体或性能范围明确记录。

## 默认入口切换前的检查

- 手动创作、模型任务、编辑器、时间线及纳入交付范围的助手能力都可在目标工程中完成闭环。
- 浏览器缓存清理后，已提交业务仍可从工程恢复；临时草稿与正式保存的区别明确。
- UI、Agent 和后台更新可交错，未提交输入和用户焦点不会被后台事件覆盖。
- 包含隐藏来源、历史版本和排队工具输入的素材删除保护有效。
- 多素材、长历史和持续后台更新时，拖动、缩放及输入性能有代表性证据。
- 服务不可用或保存失败时准确反馈；旧格式明确处理，不自动删除工程或凭证。
- 过渡接口和重复业务规则有退出方案，共用适配器与媒体能力继续保留。

## 范围管理

统一项目不自动要求制作台、完整剧作系统、通用 Workflow 产品或新的后端渲染引擎。若交付要求包含浏览器关闭后的最终视频输出，应单独明确渲染接口、资源、取消和恢复要求。

修改范围、依赖或门槛时更新本文件；任务完成与否由相应证据决定，不靠在长期路线中累计勾选状态。
